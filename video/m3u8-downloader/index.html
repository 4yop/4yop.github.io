M3U8 与 HLS 协议基础

HLS（HTTP Live Streaming）是由苹果公司在 2009 年提出的一种自适应比特率流媒体传输协议，现已成为互联网视频分发的事实标准之一。YouTube、B站、爱奇艺、Netflix 等主流平台均采用 HLS 或其变体来分发视频内容。而 M3U8 则是 HLS 协议使用的播放列表文件格式，本质上是一个 UTF-8 编码的文本文件，扩展名源自 M3U（MP3 URL）加上数字 8 表示 UTF-8 编码。

一个典型的 M3U8 文件长这样：

#EXTM3U
#EXT-X-TARGETDURATION:10
#EXT-X-VERSION:3
#EXTINF:10.0,
segment_001.ts
#EXTINF:10.0,
segment_002.ts
#EXT-X-ENDLIST

每一行都有明确含义：#EXTM3U 是文件标识头，#EXT-X-TARGETDURATION 声明每个分片的最大时长，#EXTINF 给出具体分片的时长，后面跟着的就是实际的 TS 视频分片地址。播放器按顺序逐个下载这些 TS 分片并连续播放，用户看到的就是流畅的视频画面。

为什么需要下载 M3U8 视频？

正常观看直播或点播时，浏览器会自动处理 M3U8 解析和 TS 分片下载，用户感知不到这个过程。但在以下场景中，你需要主动下载完整视频：

  • 离线存档：重要的会议录像、教学课程、直播回放需要保存到本地长期保管
  • 带宽受限环境：在网络条件差的地方提前下载好，避免播放时反复缓冲
  • 二次剪辑：将下载的素材导入 Premiere、Final Cut Pro 或剪映进行后期加工
  • 内容分析：研究人员需要逐帧检查视频内容，本地文件更便于用 FFmpeg 等工具处理
  • 平台迁移：将某个平台的独家内容备份后转移到其他设备观看

工具工作流程详解

本工具将整个下载过程拆分为以下阶段，每个阶段都设计了容错和恢复机制：

第一阶段：M3U8 解析与任务管理

输入 M3U8 地址后，工具首先发起 HTTP 请求获取播放列表原始文本。然后逐行解析，提取出所有 TS 分片的 URL 地址。如果遇到嵌套 M3U8（Master Playlist 包含多个码率的子 Playlist），工具会自动追踪到最终的媒体分片列表。解析结果以任务形式存入 IndexedDB 数据库，即使关闭浏览器也不会丢失任务队列。

第二阶段：TS 分片并行下载

这是最耗时的环节。工具采用并发下载策略，默认同时发起 6 个请求并行拉取 TS 分片。每个分片下载完成后立即标记为绿色（成功）、红色（失败）或蓝色（下载中）。为什么选 6 并发？这是经过测试的平衡点：太少则总耗时过长，太多则可能触发服务器限速甚至封禁 IP。

第三阶段：AES 解密处理

部分 M3U8 流采用 AES-128 加密保护内容。当工具检测到 #EXT-X-KEY 标签时，会自动下载密钥文件（Key URI 指向的位置），然后用 AES-CBC 模式对每个 TS 分片进行解密。初始化向量（IV）要么从 M3U8 的 IV 属性读取，要么使用分片序号作为动态 IV。解密算法来自 hls.js 内置的 AESDecryptor 组件，经过生产环境验证的可靠实现。

第四阶段：TS 转 MP4 封装

原始 TS 分片是 MPEG-TS 容器格式，虽然大部分播放器都能识别，但兼容性远不如 MP4。工具集成了 mux.js 库（VideoJS 团队开发的专业转封装引擎），将 TS 流实时转换为 ISO BMFF（MP4）格式。转换过程包括：提取 PES 包中的 ES 流、重新组装 Access Unit、生成 MP4 的 moov/moof/mdat box 结构。最终输出的 MP4 文件可以直接在任何设备上播放，无需额外转码。

第五阶段：文件合并与下载

所有分片处理完成后，工具将它们按顺序拼接成一个完整的 Blob 对象，然后通过浏览器原生的下载机制触发文件保存。文件命名遵循「名称_主机名_时间戳」规范，方便后续管理和追溯。对于超大文件（超过浏览器内存限制的情况），还支持 StreamSaver 流式写入方案，边下载边写入磁盘，避免内存溢出。

CORS 跨域问题与解决方案

这是使用此类工具最常见的障碍。出于安全考虑，浏览器默认禁止前端 JavaScript 向不同域名发起请求。当 M3U8 地址所在的服务器没有配置 CORS（跨域资源共享）响应头时，浏览器会拦截请求，导致下载失败。

解决方案是安装浏览器 CORS 扩展插件：

  • Chrome 用户：安装 "Allow CORS: Access-Control-Allow-Origin" 扩展并在目标站点启用
  • Edge 用户：安装同名 Edge 版本扩展
  • Firefox 用户：修改 about:config 中的 security.cors.enable 配置（不推荐日常开启）

需要注意的是，CORS 扩展仅用于绕过浏览器层面的安全限制。它不会影响服务器端的实际访问控制，也不意味着你可以下载付费内容的加密密钥——那是另一层保护机制。

手机端使用完整指南

在手机浏览器中使用本工具提取 M3U8 视频，需要特别注意以下要点：

  • 浏览器选择：iOS 用户推荐使用 Safari 或 Chrome，Android 用户推荐 Chrome 或 Edge，部分国产浏览器可能限制 CORS 扩展功能
  • CORS 扩展安装：手机浏览器同样需要安装 CORS 扩展，iOS 用户可在 App Store 搜索相关扩展，Android 用户需从官方扩展商店安装
  • 文件保存路径：下载完成后，文件会保存到浏览器默认下载目录，iOS 用户可在「文件」App 的「下载」文件夹找到，Android 用户可在「下载」或「文件管理」中查看
  • 大文件处理：手机内存有限，建议单个任务控制在 500MB 以内，超大视频可分段下载后用手机端剪辑工具合并
  • 网络稳定性：移动网络波动较大，建议在 WiFi 环境下操作，下载过程中避免切换网络类型（如从 WiFi 切换到 4G）

实测测试表明，在 iPhone 13 和小米 12 上，50MB 的加密 M3U8 视频完整下载耗时约 8 分钟（WiFi 环境），成功率达到 95% 以上。遇到失败分片时，工具会自动重试最多 5 次，最终仍失败的分片可通过点击红色方块手动重试。

常见问题解答

提示"需要安装 CORS 扩展"是什么意思？如何解决？

这是因为浏览器的同源策略（Same-Origin Policy）阻止了 JavaScript 向 M3U8 所在域名发起跨域请求。解决方案是在 Chrome Web Store 或 Microsoft Edge Add-ons 搜索"Allow CORS"并安装对应扩展，安装后在扩展图标上启用对当前站点的 CORS 放行权限。安装完成后刷新页面重新尝试下载即可。此操作仅影响你自己的浏览器，不会改变网站的安全配置。

下载速度很慢怎么办？可以提高并发数吗？

下载速度主要受限于两个因素：一是你的网络带宽到 M3U8 服务器的实际速率，二是服务器对单个 IP 的请求频率限制。工具默认 6 并发是一个经过测试的安全值，盲目提高并发数反而可能触发服务器的防爬机制导致 IP 被临时封禁。如果确实很慢，可以先检查网络连接是否稳定，或者尝试在网络空闲时段（如凌晨）执行下载。部分 CDN 节点对不同地区的访问速度差异很大，这也是影响因素之一。

部分分片显示红色错误，下载出来的视频会有缺失吗？

红色标记的分片表示该次下载请求失败（通常是网络超时或服务器返回错误）。工具内置了自动重试机制，每隔 2 秒会自动重试所有失败的分片。你也可以手动点击红色方块单独重试某个分片。最终如果仍有少量分片无法下载，合成的视频在这些时间段会出现画面卡顿或跳帧。建议在全部变为绿色后再进行文件合并。如果某些分片持续失败，可能是服务器端已经删除了这些过期分片。

AES 加密的视频能下载吗？安全性如何？

工具支持 AES-128-CBC 加密的 M3U8 流下载和解密。当检测到 #EXT-X-KEY 标签时会自动获取密钥并用 AES 解密每个 TS 分片。但有一种情况无法处理：如果密钥文件本身需要特殊授权才能访问（如 DRM 保护的内容），那么即使知道加密方法也无法获取密钥，自然也就无法解密。目前大多数公开的 HLS 流使用的是标准 AES-128，密钥直接放在可访问的 URL 上，这类是可以成功下载并解密的。

下载的 MP4 文件可以在手机上播放吗？

可以。工具使用 mux.js 进行 TS 到 MP4 的转封装，输出的是标准的 ISO Base Media File Format（ISO 14496-12），兼容性极好。iOS 的 Files app、Android 的自带播放器、VLC、MX Player 等主流播放器均能正常播放。如果你发现某个播放器无法打开，可能是因为视频编码格式（如 H.265/HEVC）不被该播放器支持，这种情况下建议使用 VLC 播放器，它对各种编码格式的兼容性最好。

批量下载多个视频时任务会丢失吗？

不会。工具使用 IndexedDB 数据库持久化存储任务列表，具有以下特性：数据存储在浏览器本地，关闭页面甚至重启电脑后依然存在；支持添加多个任务形成下载队列；当前任务下载完成后自动切换到下一个任务；已完成的任务会自动从数据库中删除以释放空间。唯一需要注意的是：如果在浏览器的开发者工具中手动清除 Site Data，IndexedDB 也会被一并清空，届时任务列表将丢失。

与 IDM、NDM 等下载工具相比有什么优劣？

各有适用场景。IDM（Internet Download Manager）作为成熟的桌面软件，在多线程下载速度、浏览器集成深度、断点续传稳定性方面更有优势，但它不能处理 AES 解密和 TS 转 MP4 封装——你需要分别下载每个 TS 分片再用 FFmpeg 手动合并。本工具的优势在于全链路自动化：解析 M3U8 → 下载分片 → AES 解密 → 转 MP4 → 合并下载，一站式完成。此外它是纯网页端运行，无需安装任何软件，临时使用一台公用电脑也能立刻上手。
