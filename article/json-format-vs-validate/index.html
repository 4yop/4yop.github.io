JSON 格式化和 JSON 校验有什么区别

很多人看到 JSON 出错时会先点“格式化”，但真正第一步往往应该是“校验”。这两个动作解决的问题并不一样。

格式化解决的是“看不清”

JSON 格式化主要是把压缩成一行的数据重新缩进，方便人阅读和定位字段。 它适合查看接口返回、配置文件、日志片段和复制来的 JSON 文本。格式化之后，层级、数组和对象边界会更清楚，但这不代表内容一定合法。

校验解决的是“能不能用”

JSON 校验会检查语法是否符合标准，比如双引号、逗号、括号配对、转义字符是否正确。 如果接口报错、配置加载失败，应该优先做校验，再考虑格式化。否则只是把错误排版得更好看，问题并不会消失。

最常见的错误

  • 对象最后一个字段后面多了逗号。
  • 字符串用了单引号，而不是 JSON 标准要求的双引号。
  • 从网页或文档复制时混入了不可见字符。
  • 把 JavaScript 对象当作 JSON，例如出现注释、函数或未加引号的 key。

FAQ

格式化失败是不是 JSON 一定错了？ 大多数情况下是语法有问题，建议先看校验提示的行号和列号。

接口返回很大怎么办？ 先保存原始内容，再分段检查关键字段，避免在调试时误删数据。

先说结论：校验是判断对不对，格式化是让它更好读

当一段 JSON 本身语法有问题时，格式化通常做不了任何事，因为它连解析都过不去。 这时候正确顺序应该是先校验，确认哪里报错，再回头格式化和整理结构。

两个动作分别适合什么场景

  • JSON 校验：适合排查语法错误，尤其是尾逗号、单双引号、非法注释和缺失括号。
  • JSON 格式化：适合看结构层级、对象嵌套和数组内容，让排查和阅读更轻松。
  • JSON 压缩：适合在确认无误后，生成紧凑版本放进请求参数或配置文件。

最常见的误区

误区 1： 以为格式化失败就是工具坏了。其实很多时候是 JSON 本身语法已经错了。

误区 2： 看到“压缩后没变”就以为没处理。对于本来就单行的 JSON，压缩前后差异可能本来就不大。

误区 3： 把带注释的配置文件直接当标准 JSON 处理，这类内容常常会先在校验阶段报错。
