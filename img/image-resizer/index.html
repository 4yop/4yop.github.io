图片尺寸调整器：精准控制每一像素

为什么「缩小」比「放大」更关键？

在数字图像处理领域，有一个核心原则：放大图片无法增加信息量，而缩小图片必须妥善处理信息取舍。当你把一张 4000×3000 的照片放大到 8000×6000 时，软件只能通过插值算法「猜测」不存在的像素值，结果是模糊和锯齿；但当你把同一张图缩小到 800×600 时，需要决定如何将 25 个原始像素合并为 1 个像素——这个决策过程直接影响输出图片的清晰度和视觉效果。

实际使用中，缩小操作的频率远高于放大：手机拍摄的照片通常 1200 万-4800 万像素（4000-8000px 宽），但网站展示、社交平台上传、邮件附件等场景通常只需要 800-1920px 宽度。如果不先缩小就直接使用，不仅浪费带宽和存储空间，还会导致页面加载缓慢、用户流量消耗过快等问题。

四种调整模式的使用指南

按百分比缩放
最直观的模式。输入 50% 即将宽高各缩小一半（面积变为原来的 25%）；200% 则放大一倍。适用场景：快速批量处理一组需要统一比例的图片；将高清原图统一缩小到适合网页的尺寸（如统一缩放到 50%）。注意：百分比模式保持原始宽高比不变，不会产生变形。
按固定宽度 / 固定高度
指定一个维度后，另一个维度自动按原始比例计算。适用场景：制作统一的横幅广告（所有图都设为 1200px 宽）、社交媒体封面图（如微信公众号封面 900×383px，可设宽度后裁剪高度）。这是网页设计中最常用的缩放方式——因为容器宽度通常是固定的，高度可以自适应。
按固定宽高
同时指定目标宽度和高度。适用场景：需要精确输出尺寸的场合——证件照（如 358×441 像素）、电商主图（如 800×800 正方形）、App 图标（如 1024×1024）。需要注意的是，如果目标宽高比与原图不一致，图片会被拉伸或压缩从而产生变形。本工具在处理时会尽量保持比例并居中填充超出部分。

输出格式与质量：文件大小 vs 视觉效果的平衡

调整尺寸的同时，你还可以选择输出格式和质量参数：

  • PNG：无损压缩，适合包含文字、线条、透明区域的图片（截图、图标、设计稿）。文件通常较大但不损失任何细节。
  • JPEG：有损压缩，适合照片类内容。通过质量参数（1-100）可以在文件大小和画质之间取得平衡。质量 85是一个经验上的甜点——肉眼几乎看不出与原图的区别，但文件量可以缩小 60-80%。低于 70 会出现明显的压缩伪影（块状噪点）。
  • WebP：Google 开发的新一代格式，在相同画质下比 JPEG 小 30-50%，比 PNG 小 26%。现代浏览器全面支持，是当前性价比最高的选择。如果你的用户群体使用较新的浏览器，优先推荐 WebP。

常见问题

缩小后的图片变模糊了怎么办？

轻微的清晰度下降是正常的物理限制——你把 1000万个像素的信息塞进 10万个像素里，必然丢失细节。但如果模糊程度超过预期，可能的原因是：（1）缩小幅度过大——一次性从 4000px 缩到 200px（缩小20倍），建议分步进行；（2）原图本身不够清晰——有些手机拍照虽然像素高但镜头解析力有限，「数码变焦」式的裁切也会导致模糊；（3）输出格式选择了低质量 JPEG——尝试提高质量参数到 85 以上或改用 PNG/WebP 格式。另外，确保在下载前预览确认效果满意再保存。

如何把图片变成正方形且不变形？

这是一个非常常见的需求（尤其是电商主图和社交头像）。基本思路是：先确定目标边长，然后将原图等比缩放到能完全覆盖目标尺寸的大小，最后居中裁剪超出的部分。举例：一张 1600×900 的横图要变成 800×800 的正方形——先将宽度缩放到 800（此时高度变成 450），然后以高度为准放大到 800（此时宽度变成约 1422），最后左右各裁掉 311px。这个过程叫做「缩放+裁剪」（Scale and Crop），大多数专业工具都有这个功能。如果本工具的固定宽高模式不能满足需求，可以配合站内的图片裁剪工具分步完成。

可以批量处理多张图片吗？

支持！你可以一次选择多张图片上传，所有图片会应用相同的缩放设置（相同的模式、尺寸、格式和质量参数），然后逐个预览和下载。这对于需要统一处理一批图片的场景非常有用——比如将一个相册的所有照片统一缩小到适合朋友圈的尺寸，或者将一组产品图全部转为 WebP 格式以优化网站加载速度。

EXIF 信息在缩放后会保留吗？

通过 Canvas 重绘的方式调整尺寸后，大部分 EXIF 信息会丢失——包括拍摄设备型号、GPS 定位、拍摄时间、光圈快门等元数据。这是因为 Canvas 的 `toDataURL()` / `toBlob()` 方法输出的图片只包含纯粹的像素数据，不携带原始文件的元信息。如果你需要保留 EXIF（比如版权信息、拍摄参数），建议使用专门的 EXIF 保留工具或在缩放后手动重新嵌入元数据。从隐私保护的角度看，EXIF 丢失反而是好事——分享图片时不会意外泄露位置等敏感信息。

GIF 动图缩放后还是动画吗？

不会。这是一个重要的限制：Canvas API 只能处理静态图像帧，当 GIF 被加载到 Image 对象时，浏览器只会提取其第一帧作为静态图片。如果你需要对 GIF 进行动画缩放（保留动画效果），需要使用专门的 GIF 处理库（如 gif.js）逐帧解码 → 缩放每帧 → 重新编码为 GIF。目前版本不支持此功能，后续迭代可能会加入。对于静态 GIF（只有一帧），则可以正常缩放处理。

缩放后的文件比原图还大是什么情况？

这种情况虽然听起来反直觉，但实际上很常见，原因通常有以下几种：（1）格式转换导致的膨胀——原图是高效压缩的 JPEG，你却导出为 PNG（PNG 对照片类内容的压缩效率远低于 JPEG）；（2）质量参数过高——JPEG 质量设为 100 时文件反而比质量 90 的更大，因为最高质量关闭了所有有损压缩优化；（3）放大了图片——像素总数增加了，文件自然变大。解决方案：选择合适的输出格式（照片用 JPEG/WebP，图形用 PNG），质量参数保持在 80-90 区间，避免不必要的放大操作。
